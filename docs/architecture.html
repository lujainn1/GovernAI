A use case enters through a web form or a CLI command and is checked against an SDAIA-derived risk and control library. Detection, scoring, and the final verdict are computed deterministically in code — three LLM agents narrate the findings and judge individual controls, but never invent the numbers.

1 — Submission to verdict

Both entry points run the exact same in-process pipeline — the CLI does not go through the API, it calls the orchestrator directly. Inside each of the three stages, a deterministic engine now runs before the LLM does (see Fig. 2) — the Decision Agent's verdict is the fork in the road: only one of its three outcomes can still change.

2 — Deterministic core, LLM narrates

Inside every stage, code runs before the model does. For Risk and Decision, the LLM never touches the number — it only explains a value already fixed in Python. For Policy Compliance, the LLM's judgment is the answer, but only for a fixed, code-selected list of controls — it cannot add, remove, or skip one.

3 — How risk is scored

A worked example from a real submission (the bundled loan-denial use case, examples/sample_use_case.json): eight of the 35 library risks triggered. The worst one sets the base score; each additional triggered risk adds a small, capped bump — several risk factors appearing together push the score higher than any single one of them alone.
